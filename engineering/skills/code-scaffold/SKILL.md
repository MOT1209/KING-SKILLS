# هيكل وحدة جديدة

## متى تُستخدم
- إضافة وحدة (module) أو خدمة أو مكوّن أو نقطة API جديدة إلى مشروع قائم.
- المستخدم يقول «أنشئ وحدة X على نمط بقية المشروع».

لا تُستخدم عندما: المطلوب تغيير سلوك كود قائم أو إعادة تنظيمه (`refactor-safely`).

## خطوات العمل
1. اقرأ بنية المستودع: المجلدات، `package.json` أو ما يعادله، ملفات الإعداد (lint، tsconfig، formatter).
2. اختر 2 إلى 3 وحدات قائمة مشابهة كمرجع، واقرأها كاملة: التسمية، تقسيم الملفات، طريقة الاستيراد، الحقن، الاختبارات.
3. استخرج النمط: أسماء الملفات (kebab-case أو غيره)، تسمية الأصناف والدوال، موقع الاختبارات، ملفات الفهرسة (index)، التسجيل في الوحدة الأم.
4. حدّد قائمة الملفات التي ستُنشأ وما سيُعدَّل في ملفات موجودة (تسجيل الوحدة، المسارات)، واعرضها قبل الإنشاء إن كان العدد كبيراً.
5. أنشئ الهيكل بأقل منطق ممكن: واجهات وأنواع وتوقيعات وتنفيذ بسيط يعمل، لا منطق عمل مخمَّن.
6. أنشئ اختباراً أولياً يمرّ ويثبت أن الهيكل مسجَّل ويعمل.
7. شغّل الفحوصات المتاحة (بناء، lint، اختبارات) وأصلح ما كسره الهيكل.
8. اعرض ملخصاً بالملفات المنشأة والمعدَّلة وما بقي للمستخدم.

## صيغة المخرجات
قائمة الملفات (منشأ/معدَّل) بمساراتها، محتوى كل ملف، نتيجة تشغيل الفحوصات، وقائمة «التالي» القصيرة.

## قواعد وحدود
- التزم بنمط المستودع حتى لو خالف تفضيلك؛ لا تُدخل نمطاً جديداً دون ذكر السبب.
- لا تضف اعتماديات جديدة دون موافقة.
- لا تكتب منطق عمل لم يُطلب؛ استخدم TODO واضحاً حيث يلزم قرار.
- لا تضع أسراراً أو بيانات حقيقية في الأمثلة والإعدادات.
- لا تُعدّل الوحدات المرجعية.

## حالات حدّية
- لا توجد وحدة مشابهة: اتبع أعراف الإطار الرسمية واذكر ذلك.
- مرجعان متعارضان في النمط: اتبع الأحدث أو الأكثر استخداماً واذكر الاختيار.
- فشل البناء بسبب تعارض لا علاقة له بالهيكل: لا تُصلحه سراً؛ أبلغ به.
- مستودع أحادي (monorepo): التزم حدود الحزم وملفات الإعداد لكل حزمة.

## مثال كامل
### المدخل
«أنشئ وحدة `invoices` في مشروع NestJS على نمط وحدة `orders` الموجودة.»

### المخرج
بعد قراءة `src/orders/` (ملفات: `orders.module.ts`، `orders.controller.ts`، `orders.service.ts`، `dto/`، `orders.service.spec.ts`):
```
منشأ:  src/invoices/invoices.module.ts
منشأ:  src/invoices/invoices.controller.ts
منشأ:  src/invoices/invoices.service.ts
منشأ:  src/invoices/dto/create-invoice.dto.ts
منشأ:  src/invoices/invoices.service.spec.ts
معدَّل: src/app.module.ts  (استيراد InvoicesModule)
```
```ts
// src/invoices/invoices.service.ts
@Injectable()
export class InvoicesService {
  findAll(): Invoice[] {
    // TODO: ربط مصدر البيانات بعد اعتماد المخطط
    return [];
  }
}
```
الفحوصات: `build` نجح، `lint` نجح، اختبار واحد مرّ. التالي: تحديد حقول `Invoice` ومصدر البيانات.
