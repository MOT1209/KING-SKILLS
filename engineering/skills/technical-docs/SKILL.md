# التوثيق التقني

## متى تُستخدم
- توثيق وحدة أو دالة أو واجهة API أو أداة داخلية.
- كتابة README لمشروع أو دليل بدء سريع.
- تحديث توثيق تقادم بعد تغيير الكود.

لا تُستخدم عندما: المطلوب تقرير حادث (`incident-postmortem`) أو قرار معماري (`architecture-decision`).

## خطوات العمل
1. حدّد الجمهور (مطوّر جديد، مستهلك API، مشغّل) وما يريد إنجازه، فهذا يحدد العمق.
2. اقرأ الكود الفعلي والاختبارات، ولا توثّق من الأسماء وحدها. شغّل الأوامر والأمثلة لتعرف السلوك الحقيقي.
3. ابنِ الهيكل: ما هذه الأداة ولماذا، التثبيت والمتطلبات، بدء سريع بمثال يعمل، المرجع (التوقيعات والمعاملات والقيم المرجعة والأخطاء)، أمثلة متقدمة، قيود وأسئلة شائعة.
4. اكتب لكل عنصر عام: الغرض بجملة، المعاملات بأنواعها وإلزاميتها وقيمها الافتراضية، القيمة المرجعة، الأخطاء المحتملة.
5. اكتب أمثلة صغيرة كاملة قابلة للنسخ والتشغيل، ثم **شغّلها فعلياً** وانسخ المخرجات الحقيقية في التوثيق.
6. وثّق الأخطاء الشائعة وطرق حلها، والقيود المعروفة، والتوافق (الإصدارات).
7. اتّسق في المصطلحات والتنسيق، واربط بين الصفحات والأقسام.
8. أضف تاريخ آخر مراجعة أو إصداراً مرتبطاً إن كان للمستودع نمط لذلك، وقائمة بما لم يُغطَّ.

## صيغة المخرجات
ملف Markdown (أو صيغة المستودع) بالأقسام: نظرة عامة، التثبيت، بدء سريع، المرجع، أمثلة، الأخطاء، القيود.

## قواعد وحدود
- كل مثال يجب أن يكون قد نُفّذ فعلاً، والمخرجات المعروضة هي المخرجات الحقيقية.
- لا تضع أسراراً أو بيانات حقيقية أو عناوين داخلية في الأمثلة؛ استخدم قيماً وهمية واضحة.
- لا تصف سلوكاً غير موجود أو مخططاً له كأنه قائم.
- لا تختلق أرقام إصدارات أو معايير أداء.
- أبقِ التوثيق قريباً من الكود (نفس المستودع) قدر الإمكان.

## قائمة تحقق
- كل مثال شُغّل وناتجه حقيقي.
- كل معامل عام موثّق بنوعه وقيمته الافتراضية.
- الأخطاء والقيود مذكورة.
- لا بيانات حساسة.

## حالات حدّية
- كود بلا اختبارات وسلوك غامض: وثّق ما تحققت منه فعلاً وعلّم الباقي «غير مؤكد».
- واجهة ثنائية اللغة أو RTL: أضف مثالاً بنص عربي إن كانت الأداة تعالج نصوصاً.
- واجهة قيد التغيير: وسمها تجريبية صراحة.
- توثيق عربي لكود بأسماء إنجليزية: أبقِ الأسماء البرمجية كما هي داخل علامات الكود.

## مثال كامل
### المدخل
```js
export function slugify(text) {
  return text.trim().toLowerCase().replace(/[^\p{L}\p{N}]+/gu, "-").replace(/^-+|-+$/g, "");
}
```
### المخرج
````markdown
## slugify(text)

يحوّل نصاً إلى معرّف صالح للروابط: أحرف صغيرة، وكل تسلسل غير حرفي/رقمي يتحوّل إلى `-`.

**المعاملات**
| الاسم | النوع | مطلوب | الوصف |
|---|---|---|---|
| `text` | `string` | نعم | النص المراد تحويله |

**القيمة المرجعة:** `string` — قد تكون فارغة إذا لم يحوِ النص أحرفاً أو أرقاماً.

**أمثلة** (نُفّذت فعلاً)
```js
slugify("  Hello, World!  ");     // "hello-world"
slugify("مرحبا بالعالم");          // "مرحبا-بالعالم"
slugify("!!!");                   // ""
slugify("Node.js 22 Release");    // "node-js-22-release"
```

**قيود:** يمرّر `text` غير نصي خطأً في `trim`؛ التحقق من النوع مسؤولية المستدعي.
````
