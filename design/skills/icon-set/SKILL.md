# مجموعة الأيقونات

## متى تُستخدم
- بناء مجموعة أيقونات لتطبيق أو علامة من الصفر.
- توحيد أيقونات مختلفة المصدر ظاهرة التباين في الأسلوب.
- تحديد حالات الأيقونات في نظام تصميم.

## خطوات العمل
1. حدّد قائمة الأيقونات المطلوبة ووظيفة كل منها، ومنصة الاستخدام، والأحجام المطلوبة.
2. ثبّت المواصفات الأساسية للمجموعة:
   - **شبكة الرسم (Grid):** مقاس اللوحة وهامش الأمان (مثل 24×24 مع هامش داخلي).
   - **سماكة الخط (Stroke):** قيمة واحدة لكل المجموعة.
   - **الأسلوب:** خطي أو ممتلئ أو مزدوج، ولا تخلط.
   - **الزوايا والنهايات:** نصف قطر الزوايا، ونهايات الخطوط (مستديرة أو مسطحة).
   - **الشكل الأساسي:** أشكال مفتاحية (دائرة، مربع، مستطيل رأسي وأفقي) تُرسم بحجم بصري متقارب.
3. صنّف الأيقونات: وظيفية (إجراءات)، حالة، تنقل، محتوى. وحدّد التي تتأثر باتجاه RTL (الاتجاهية تنعكس، وغير الاتجاهية لا).
4. حدّد **الحالات** لكل أيقونة: عادية (Default)، نشطة/محددة (Active/Selected)، معطلة (Disabled)، ويمكن إضافة تمرير (Hover) وتركيز (Focus) وضغط (Pressed). لكل حالة: اللون ودور اللون في لوحة الألوان، وسماكة أو امتلاء إن اختلف، والتباين.
5. اشترط ألا تعتمد الحالة على اللون وحده، مثل تغيير الأسلوب من خطي إلى ممتلئ للنشط (WCAG SC 1.4.1)، وأن يحقق لون الأيقونة الضرورية تبايناً 3:1 على الأقل (SC 1.4.11).
6. سمِّ الأيقونات بصيغة ثابتة (مثل `icon-search`، `icon-arrow-start`) واستخدم `start/end` بدل `left/right` للاتجاهية.
7. أنتج SVG نظيفاً عند الطلب: `viewBox` موحّد، `fill`/`stroke` بقيمة `currentColor`، بلا تحويلات زائدة، وبنصوص بديلة عند الاستخدام.
8. اختبر: التصغير إلى أصغر مقاس مستخدم، التجانب البصري جنب بعضها، والوضوح بالخلفيات الفاتحة والداكنة.

## صيغة المخرجات
1. **مواصفات المجموعة:** جدول (البند | القيمة): الشبكة، الهامش، السماكة، الأسلوب، الزوايا، النهايات.
2. **قائمة الأيقونات:** (الاسم | الوظيفة | اتجاهية؟ | ملاحظة RTL).
3. **جدول الحالات:** (الحالة | اللون/الدور | التغيير الشكلي | التباين).
4. **قواعد التسمية.**
5. **SVG** لأيقونة أو أكثر عند الطلب فقط.

## مثال كامل
**المدخل:** «مواصفات مجموعة أيقونات خطية لتطبيق، 3 أيقونات: بحث، رجوع، إعدادات.»

**المخرج المتوقع:**
```text
| البند | القيمة (يعتمدها فريقك) |
|---|---|
| الشبكة | 24×24، هامش داخلي 2 |
| السماكة | 2 (قيمة واحدة للمجموعة) |
| الأسلوب | خطي |
| الزوايا والنهايات | نصف قطر 2، نهايات مستديرة |

| الاسم | الوظيفة | اتجاهية؟ |
|---|---|---|
| icon-search | بحث | لا (المقبض قد يُعكس بقرار تصميمي) |
| icon-arrow-start | رجوع | نعم، تنعكس في RTL |
| icon-settings | إعدادات | لا |

| الحالة | اللون | التغيير الشكلي |
|---|---|---|
| عادية | text-secondary | خطي |
| نشطة | primary | ممتلئ (إشارة غير لونية) |
| معطلة | text-disabled | خطي |

SVG بسيط لـ icon-search:
<svg viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2"
     stroke-linecap="round" aria-hidden="true">
  <circle cx="11" cy="11" r="6"/><path d="M16 16l4 4"/>
</svg>
```

## حالات حدّية
- **أيقونات واردة بسماكات مختلفة:** حدّد سماكة المجموعة، وسجّل الأيقونات التي تحتاج إعادة رسم.
- **أيقونات من مصدر مرخّص:** اطلب الرخصة وتحقق منها قبل الدمج، ولا تفترض أنها مفتوحة.
- **أيقونة يختلف معناها بحسب الثقافة:** نبّه إلى ذلك واقترح بديلاً أو نصاً مرافقاً.
- **حالة نشطة لا تتمايز عن العادية إلا باللون:** اقترح تغييراً شكلياً إضافياً.
- **حجم مستخدم أصغر من الشبكة:** اختبر الوضوح وبسّط التفاصيل لتلك الأحجام.
- **أيقونة اتجاهية لا يعرف المستخدم أتنعكس أم لا:** قرّر بمعناها (تقدم/رجوع تنعكس) واذكر السبب.

## قواعد وحدود
- لا تنسخ أيقونات من مجموعات مرخصة بغير رخصة تسمح؛ تحقق من رخصة أي مجموعة جاهزة.
- لا تخلط سماكتين أو أسلوبين في مجموعة واحدة.
- أرقام الشبكة والسماكة قيم يختارها المستخدم/النظام؛ لا تقدّمها كمعيار عالمي.
- الرموز المحمّلة ثقافياً (إيماءات اليد، الحيوانات) تُراجع قبل الاعتماد.
- لا تستخدم أيقونة بمعنى مختلف عن شائع استخدامها دون سبب.
