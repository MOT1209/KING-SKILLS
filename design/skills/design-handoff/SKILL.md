# تسليم التصميم

## متى تُستخدم
- تسليم شاشات أو مكونات للتنفيذ.
- بناء توثيق أو رموز تصميم (Design Tokens).
- مواءمة ما نُفّذ مع التصميم الأصلي.

## خطوات العمل
1. اجمع المصدر: ملفات التصميم أو اللقطات أو القيم المعتمدة. لا تنشئ قيماً لم ترد فيه؛ اطلبها أو علّمها [يُستكمل].
2. استخرج **الرموز (Tokens)** بقيم دقيقة وأسماء دلالية ثابتة:
   - الألوان: HEX/RGB واسم الدور (مثل `color-primary-600`، `color-text-default`).
   - الطباعة: العائلة، المقاس، الوزن، ارتفاع السطر لكل دور نصي، للعربية واللاتينية.
   - المسافات: السلّم المعتمد، والهوامش والحشوات لكل مكوّن.
   - الزوايا والظلال والحدود والتباين.
3. سمِّ المكونات بنمط ثابت (مثل `Button/Primary`، `Input/Text`) واستخدم الاسم نفسه في التصميم والكود والوثائق.
4. لكل مكوّن اذكر: المقاسات (العرض/الارتفاع أو سلوك التمدد)، المسافات الداخلية، المحاذاة، سلوك النص الطويل (قص أو التفاف)، ومتغيرات الأحجام.
5. أرفق **حالات التفاعل** لكل مكوّن تفاعلي: عادي، تمرير (Hover)، تركيز (Focus)، ضغط (Pressed)، تعطيل (Disabled)، وحالات خاصة (تحميل، خطأ، نجاح). ضع القيم المتغيرة لكل حالة، مثل اللون والحد والظل.
6. وثّق RTL: ما ينعكس، المحاذاة، اتجاه الأيقونات، والمسافات المنطقية (start/end).
7. حدّد الأصول وصيغها: SVG للأيقونات، وصيغ ومقاسات الصور (1x/2x)، وقواعد التسمية.
8. دوّن السلوك الديناميكي: الحركة والانتقالات (المدة والمنحنى إن وُجدا في التصميم)، والاستجابة عند نقاط العرض.
9. قدّم قائمة تحقق للمراجعة: ما الذي يقارنه المطوّر بالتصميم قبل الإغلاق.

## صيغة المخرجات
1. **نطاق التسليم:** المكونات والشاشات المشمولة، ومصدر القيم.
2. **جدول الرموز (Tokens)** أو JSON بالأسماء الدلالية والقيم.
3. **توثيق كل مكوّن:** المقاسات، المسافات، المحاذاة، والمتغيرات.
4. **جدول الحالات:** (الحالة | القيم المتغيرة).
5. **ملاحظات RTL والأصول والحركة.**
6. **أسئلة مفتوحة** (قيم ناقصة أو تعارضات).
7. **قائمة تحقق للمراجعة.**

## مثال كامل
**المدخل:** «وثّق زر التطبيق الرئيس. من التصميم: الخلفية #1F6F5C، النص #FFFFFF، الارتفاع 48، الحشو الأفقي 24، الزوايا 8، الخط 16 وزن 600. عند التمرير تصبح الخلفية #195A4B.»

**المخرج المتوقع:**
```text
مصدر القيم: ما قدّمته أنت فقط.

{
  "color-primary-600": "#1F6F5C",
  "color-primary-700": "#195A4B",
  "color-on-primary": "#FFFFFF",
  "radius-md": "8px"
}

Button/Primary
- الارتفاع 48px؛ الحشو الأفقي 24px؛ الزوايا radius-md.
- النص 16px، وزن 600.
- النص الطويل: [يُستكمل: قص أم التفاف؟]

| الحالة | الخلفية | ملاحظة |
|---|---|---|
| عادي | color-primary-600 | |
| تمرير | color-primary-700 | |
| تركيز | [يُستكمل] | لم تُقدَّم قيمة الحلقة |
| ضغط | [يُستكمل] | |
| تعطيل | [يُستكمل] | |

RTL: الحشو بصيغة padding-inline، والأيقونة الاتجاهية تنعكس.
أسئلة مفتوحة: حالات التركيز والضغط والتعطيل، وسلوك النص الطويل.
قائمة التحقق: الألوان، الأبعاد، الحالات، سلوك RTL.
```

## حالات حدّية
- **قيمة غير مقدَّمة في التصميم:** ضعها [يُستكمل] واسأل عنها، ولا تقرّب من قيمة مجاورة.
- **قيمتان مختلفتان للعنصر نفسه في موضعين:** أبلغ عن التعارض واطلب المرجع قبل التوثيق.
- **مكوّن بلا حالة تركيز:** سجّله نقصاً في التسليم، ولا تتجاوزه.
- **أسماء غير متسقة بين التصميم والكود:** اقترح اسماً موحّداً، وأبقِ الاسمين مقابل بعضهما مؤقتاً.
- **تصميم يخالف قاعدة الوصول (تباين منخفض):** وثّقه كما هو وارفع ملاحظة منفصلة، ولا تعدّله بنفسك.
- **الفريق يريد صيغة محددة (CSS variables مثلاً):** حوّل المخرجات إليها بالقيم نفسها.

## قواعد وحدود
- كل قيمة رقمية تأتي من ملف التصميم أو المستخدم؛ لا تقدّر ولا تقرّب.
- لا تغيّر التصميم أثناء التسليم؛ سجّل أي تعارض أو نقص كسؤال.
- استخدم أسماء ثابتة لا تتغير بين الوثائق.
- لا تُهمل الحالات؛ مكوّن بلا حالة تركيز أو تعطيل ناقص.
- نسّق المخرجات بصيغة تناسب الفريق (جدول، JSON للرموز، Markdown).
